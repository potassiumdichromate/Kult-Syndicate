# Switchyard 0.6 UX handoff

The default experience is the bundled Three.js district. See `../DEPLOY.md` for current routing and integration; older root-path routing instructions are superseded.

- Named landmarks open mission briefs. Selecting a building does not charge Supplies. The server charges only on mission commitment and allowed decisions.
- The next stop follows the current mission or the Scout → Heist → Workshop journey. A completed route report and its dependent Heist remain visible as real operation state.
- Desktop keeps the Agent console beside the map. At 850px and below, a native modal drawer holds the same console, with focus containment and a Back to district control. Closing it does not cancel the job.
- Drag to pan, pinch/scroll or +/− to zoom, and use reset to recover the district view. Keyboard map controls are arrows, +/− and 0. Tab/Enter work on location pins and toolbar controls.
- Labels can be reduced to icons. Secondary pins are compact on mobile; accessible names remain. Prioritized labels avoid other pins and the top interface.
- Low graphics mode removes shadows and uses a 1x pixel ratio. Balanced mode caps device ratio at 1.6. Decorative motion respects reduced-motion preferences. Rendering pauses while the district is hidden.
- WebGL failure or context loss returns to Canvas. List view exposes the same locations and missions. No rewards depend on visual movement.
- `?embed=1` compacts duplicate branding while retaining District, Play & hire, Passport, Crew and Permissions navigation.
- The optional old Godot client is hidden unless `?legacy=1` is provided. It has not received the new UI.

Browser evidence is recorded in `RELEASE_0.6.0.md`. Screenshots generated by the tests are internal QA output, excluded from the shipped ZIP.
